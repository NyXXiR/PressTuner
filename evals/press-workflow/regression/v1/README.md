# 사람 확인 결함에서 만든 회귀 조건

`manifest.json`은 기존 synthetic C01 입력에 실제 사람이 남긴 결함 판정에서 승격했다. 새로운 출력은 해당 기준을 충족해야 한다는 회귀 요구사항이지, 과거 출력의 정답 라벨을 미래 출력에 복사하는 것이 아니다.

- 사실 근거와 과장 두 기준, 중복 출력에서 나온 과장은 원문/기준 단위 하나로 합쳤다.
- 원래 사람 이름/자유 서술/초안은 포함하지 않는다. source artifact/review/output hash로 이력을 연결한다.
- G-Eval rubric/model identity가 바뀌면 실행이 거절된다. 기존 사람 라벨을 같은 출력의 새 평가에 명시적으로 연결하고 재승격한다. 다른 생성 결과로 라벨을 옮기지 않는다.
- 2026-10-12 기존 후보 결과에 적용한 회귀 gate는 `REGRESSION`, exit 1이었다. 빨간 결과를 정상으로 바꾸지 않는다.
- 같은 개발 입력에 개선 recipe를 적용해 새로 생성한 후보는 exit 0이었다. 사람 재검토와 독립 개선 입증은 없으며, [실측 보고서](../../../../docs/ai/press-workflow/EVALUATION_SYSTEM_RESULTS.md)에 두 결과와 평가기의 남은 오류를 함께 기록했다.
- GitHub Actions의 무료 job은 계약/브라우저 QA를 실행한다. 수동 실행의 `run_model_regression`을 선택하면 두 초안을 새로 생성하고 공식 Ragas/G-Eval 평가 후 이 조건을 검사한다. 기존 기본 후보가 실패할 수 있으며 그것이 이 테스트의 목적이다.
- CI 성공은 이 좁은 입력/기준에서 회귀를 발견하지 못했다는 뜻이다. 평가기 신뢰도나 운영 채택 허가가 아니다.
