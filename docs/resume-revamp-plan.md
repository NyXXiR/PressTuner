# brieFFlow Resume UI Revamp Plan

## 1. 목표

현재 자소서 UX는 기능은 많지만 사용자가 해야 할 일보다 화면이 먼저 보이는 구조다. 이번 개편의 목적은 사용자가 아래 한 흐름만 따라가면 되도록 만드는 것이다.

1. 경험 브릭 생성
2. 자소서 문항 수집
3. 문항별 초안 생성
4. 설계도 기반으로 다듬기
5. 완료 후 경험 브릭 자산으로 환류

핵심 원칙은 `step by step`, `사용자 제어감`, `작업 연속감`, `완료 성취감`이다.

## 2. 현재 구조 진단

현재 구현은 대체로 아래 흐름이다.

- `/resume/dashboard`
  경험 브릭 생성, 작성 중 지원서, 목표 관리가 한 화면에 섞여 있음
- `/resume/bricks`
  브릭 라이브러리 관리와 PDF 파싱이 함께 있음
- `/resume/write`
  `SETUP -> STRATEGY -> FOCUS` 구조
- `SetupStep`
  회사명, 직무, JD, 문항 리스트를 한 번에 많이 입력해야 함
- `FocusStep`
  채팅, 브릭 선택, 유사 문항, 편입, 첨삭이 동시에 노출됨

문제는 다음과 같다.

- 첫 진입 시 무엇부터 해야 하는지 직관적이지 않음
- 문항 입력 단계의 인지 부담이 큼
- 질문 작성과 답변 작성 사이의 전환이 사용자의 액션이 아니라 시스템 중심처럼 느껴짐
- 문항 간 이동은 유지되지만 UI 인상이 “페이지 이동”처럼 보여 작업 연속감이 약함
- 성취감을 주는 진행 구조보다 편집 도구가 먼저 보임
- 경험 브릭 환류 기능은 일부 존재하지만 핵심 플로우의 중심이 아니라 숨겨져 있음

## 3. 개편 후 사용자 여정

### Step 1. 경험 브릭 만들기

목표는 “자소서 쓰기 전에 재료부터 모으기”를 분명하게 만드는 것이다.

- 기본 진입 메시지:
  `먼저 내 경험을 불러와 재사용 가능한 브릭으로 정리합니다.`
- 유지 기능:
  잡코리아 / 사람인 이력서 파싱
  PDF 파싱
  수동 입력
- 결과 화면:
  생성된 브릭 개수, 대표 태그, 추천 활용 예시
- 다음 액션:
  자동 이동하지 않고 `이 문항으로 자소서 시작하기` 버튼을 눌러 다음 단계로 이동

### Step 2. 자소서 문항 모으기

이 단계는 최대한 단순해야 한다. 기존 `company / job / jd / question list` 전체 편집 중심 화면을 입력 도우미 중심으로 바꾼다.

- 핵심 UI는 큰 `textarea` 하나
- 안내 문구:
  `자소서 문항을 한 번에 붙여넣거나, 채용 공고 주소를 넣어주세요. AI가 문항만 보기 좋게 정리합니다.`
- 입력 방식 2개 지원
  1. 복붙 모드
  2. URL 모드

복붙 모드:

- 사용자가 채용 페이지나 공고의 자소서 문항 부분을 드래그해서 그대로 붙여넣음
- AI가 문항, 글자 수 제한, 선택형 메타 정보를 구조화

URL 모드:

- 사용자가 채용 공고 URL 입력
- 서버가 페이지를 수집
- AI가 자소서 문항만 정리해서 카드 리스트로 변환

정리 결과 영역:

- 문항 카드를 보기 좋게 세로 정렬
- 각 카드에는:
  문항 번호
  문항 텍스트
  글자 수 제한
  편집 버튼
  삭제 버튼
- 하단 CTA:
  `이 문항들로 초안 만들기`

중요한 UX 규칙:

- 문항 정리 후에도 바로 다음 단계로 자동 이동하지 않음
- 사용자가 CTA를 눌러야 다음 단계로 진입
- 이 시점에 사용자가 “내가 흐름을 제어하고 있다”는 감각을 가져야 함

### Step 3. 문항별 초안 생성 시작

이 단계에서 처음으로 문항별 작업 화면으로 들어간다. 그러나 문항마다 별도 페이지로 들어가는 인상은 줄여야 한다.

- 구조:
  단일 워크스페이스 안에서 질문만 바뀌는 방식
- 상단:
  전체 진행률 바
  현재 문항 번호
  완료 개수
- 좌측 또는 상단:
  문항 리스트 사이드 레일
- 메인:
  현재 문항, 초안 생성, 편집

초기 상태에서는 기능보다 액션이 먼저 보여야 한다.

- 현재 문항
- 선택된 관련 브릭 요약
- 메인 CTA:
  `이 문항 초안 만들기`

초안 생성이 끝나면 그 다음부터 기존 설계도 기반 편집 UX로 자연스럽게 확장한다.

### Step 4. 기존 설계도 방식으로 심화 편집

기존 `StrategyStep`, `FocusStep`의 강점은 버리지 않는다. 다만 초기 노출 밀도를 낮춘다.

- 초안 생성 전:
  단순 모드
- 초안 생성 후:
  고급 모드 확장

초안 생성 후 노출되는 영역:

- 설계도 요약
- 선택 브릭
- AI 첨삭 / 재작성
- 유사 문항 재활용
- 새 경험 편입 제안

즉, 고급 기능은 “처음부터 다 보여주는 것”이 아니라 “초안이 생긴 뒤 확장되는 패널”로 바꾼다.

### Step 5. 완료와 경험 브릭 환류

문항 완료는 단순 저장이 아니라 자산 축적의 순간으로 보여야 한다.

- 문항 저장 시 AI가 아래를 판단
  이 답변에 새 경험이 있는가
  기존 브릭의 보강 소재인가
  이미 있는 경험의 재표현인가
- 결과 액션
  새 브릭 자동 추가
  기존 브릭 보강 제안
  링크만 유지

권장 UX:

- 기본은 `제안 후 승인`
- 사용자가 원하면 팀 설정 또는 개인 설정에서 `자동 추가` 선택 가능

완료 피드백 예시:

- `이 문항에서 새로운 경험 1개를 발견했어요`
- `기존 브릭 2개를 더 풍부하게 만들 수 있어요`
- `지금 반영하기` / `나중에 보기`

## 4. 새 정보 구조

권장 정보 구조는 아래와 같다.

### A. `/resume/dashboard`

대시보드는 “여기서 다 한다”가 아니라 “어디서부터 시작할지 정한다”로 축소한다.

- 상단 1개 메인 카드:
  `처음부터 자소서 시작`
- 상태별 진입:
  경험 브릭 0개면 Step 1 유도
  브릭 있음, 문항 없음이면 Step 2 유도
  작성 중이면 마지막 문항 이어쓰기 유도
- 보조 영역:
  최근 작성 중 항목
  완료 개수
  브릭 자산 개수

### B. `/resume/bricks`

브릭 보관함의 역할은 유지하되, 온보딩 모드와 관리 모드를 분리한다.

- 온보딩 모드:
  수집과 생성 중심
- 관리 모드:
  검색, 수정, 중복 정리 중심

### C. `/resume/write`

하나의 워크스페이스로 유지하되 내부 단계를 아래처럼 재구성한다.

- `COLLECT`
  문항 수집
- `PLAN`
  문항 리스트 확인 및 시작
- `DRAFT`
  문항별 초안 생성/편집
- `REFINE`
  설계도, 첨삭, 브릭 관리 확장
- `COMPLETE`
  완료와 브릭 환류

현재 `SETUP`, `STRATEGY`, `FOCUS`는 아래처럼 매핑 가능하다.

- `SETUP` -> `COLLECT` + `PLAN`으로 분리
- `STRATEGY` -> 질문 리스트 중심 `PLAN`
- `FOCUS` -> `DRAFT` + `REFINE`

## 5. 핵심 화면 설계

### 화면 1. 경험 브릭 온보딩

주요 메시지:
`이력서에서 경험을 꺼내 자소서 재료로 바꿉니다.`

필수 요소:

- 파싱 소스 선택
  잡코리아
  사람인
  PDF
  직접 입력
- 생성된 브릭 미리보기
- 저장 후 CTA
  `문항 입력하러 가기`

### 화면 2. 문항 수집 화면

주요 메시지:
`이번에는 문항만 모읍니다. 형식은 AI가 정리합니다.`

레이아웃:

- 상단 설명
- 입력 탭 2개
  `내용 붙여넣기`
  `공고 주소로 가져오기`
- 중앙 대형 입력 영역
- 하단 결과 리스트
- sticky CTA
  `정리된 문항으로 시작하기`

보조 UX:

- 예시 placeholder를 아주 구체적으로 제공
- URL 모드에서는 수집 상태를 단계별로 노출
  `공고 확인 중 -> 본문 수집 중 -> 문항 정리 중`

### 화면 3. 문항 진행 워크스페이스

목표:
문항 이동이 “페이지 전환”이 아니라 “같은 작업대에서 다음 카드로 넘기는 것”처럼 느껴져야 한다.

레이아웃:

- 상단 고정 헤더
  지원 회사 / 직무
  전체 진행률
  `3 / 7 완료`
- 좌측 레일 또는 상단 캐러셀
  모든 문항 목록
  상태 아이콘
  현재 문항 강조
- 메인 패널
  문항 본문
  선택 브릭 요약
  초안 에디터
- 보조 패널
  AI 도움, 설계도, 유사 문항, 브릭 편입

문항 전환 규칙:

- 같은 route 내 index만 변경
- 클라이언트 상태는 유지
- 전환 애니메이션은 카드 슬라이드 수준으로 제한
- 브라우저 전체 새로고침 인상을 주는 loader 금지

### 화면 4. 완료 피드백

성취감을 분명하게 줘야 한다.

- 한 문항 완료 시:
  체크 애니메이션
  진행률 증가
  `다음 문항 열기`
- 전체 완료 시:
  요약 카드
  완료 문항 수
  새로 생긴 브릭 수
  보강 제안 수
  `전체 검토하기`
  `경험 브릭 반영하기`

## 6. 상태 관리 원칙

작업 연속감을 위해 상태 보존 전략이 중요하다.

### 필수 원칙

- 문항 작성 도중 route를 바꾸지 않는다
- 같은 application 안에서는 store를 유지한다
- 저장은 autosave + 명시 저장을 병행한다
- 질문 전환 시 로컬 draft를 유지한다
- 네트워크 저장 실패 시에도 에디터 내용은 남긴다

### 권장 저장 구조

- 서버 저장:
  application, question, relatedBricks, completion 상태
- 클라이언트 임시 저장:
  현재 문항 텍스트
  아직 서버 저장 전 수정분
  현재 열려 있는 패널 상태
  사용자가 마지막으로 보고 있던 문항 index

권장 구현:

- `useResumeWriteStore`에 draft persistence 추가
- `appId` 기준 `sessionStorage` 또는 `localStorage` 임시 저장
- debounce autosave 도입

예시:

- 800ms debounce 로컬 임시 저장
- 3초 idle 또는 문항 전환 시 서버 저장
- “저장됨 / 로컬 보관 중 / 동기화 실패” 상태 표시

## 7. 성취감 설계

이 프로젝트의 핵심은 단순 편집기가 아니라 “하나씩 끝내는 경험”이다.

필수 요소:

- 전체 진행률 바
- 문항별 체크 상태
- `완료한 문항`과 `남은 문항`이 시각적으로 분리
- 완료 직후 즉시 보상 메시지
- 마지막 문항 완료 시 리캡 화면

추천 UI 장치:

- 문항 카드에 완료 스탬프
- 진행률 바에 작은 milestone
- `첫 문항 완료`, `절반 완료`, `전체 완료` 피드백
- 브릭 자산 증가를 숫자로 보여주기

## 8. 경험 브릭 환류 사이클

이 기능은 개편의 차별점이다.

### 트리거

- 문항 최종 확정 시
- 전체 완료 시 일괄 재분석 가능

### AI 판단 분류

1. 새 경험이므로 새 브릭 후보 생성
2. 기존 브릭을 더 풍부하게 만드는 보강 후보
3. 이미 있는 브릭의 재사용이므로 링크만 유지

### UX 방식

- 문항 저장 후 하단 토스트 또는 사이드 시트
- 항목별로 아래 액션 제공
  `새 브릭으로 저장`
  `기존 브릭 보강`
  `이번엔 보류`

현재 `FocusStep`에 있는 편입 로직은 유지 가능하되, 발견 타이밍을 “자연어 명령 기반”에서 “문항 완료 후 시스템 제안 기반”으로 끌어올리는 것이 좋다.

## 9. 검색/재사용 전략

사용자가 원하는 것은 제목 검색보다 “예전에 비슷한 질문에 뭐라고 썼지?”를 찾는 것이다.

### 최소 요구사항

- 문자열 검색
- 기업명 / 직무 / 태그 / 문항 내용 필터

### 목표 기능

- 자연어 기반 의미 검색
- 예시 질의:
  `예전에 협업 갈등 해결 썼던 답변 보여줘`
  `백엔드 장애 대응 경험 들어간 자소서 찾아줘`

### 구현 방향

- 답변 단위 임베딩 저장
- 문항 텍스트 + 답변 + 연결 브릭 + 회사/직무 메타를 합친 searchable document 생성
- `/resume/questions` 검색을 키워드 검색 + semantic retrieval 혼합 방식으로 확장

우선순위:

1. 기존 유사 문항 검색 품질 개선
2. 답변 단위 semantic search API 추가
3. 브릭 검색과 답변 검색을 통합한 AI 검색 인터페이스 추가

## 10. 재사용 가능한 기존 자산

완전히 새로 만들 필요는 없다. 현재 코드에서 아래는 재사용 가치가 높다.

- `/resume/bricks`의 파싱 및 저장 로직
- `useResumeWriteStore`의 application/question 저장 구조
- `generateStrategy`
- `FocusStep`의 유사 문항 찾기
- `FocusStep`의 브릭 편입 API

반대로 재구성이 필요한 부분은 아래다.

- `SetupStep`
  입력 밀도 축소 필요
- `StrategyStep`
  설계도 보기보다 “문항 진행 허브”로 재정의 필요
- `FocusStep`
  초기 노출 복잡도 축소, progressive disclosure 필요
- `dashboard`
  기능 혼합을 줄이고 next best action 중심으로 재배치 필요

## 12. 바로 다음 작업 권장안

가장 먼저 손대야 할 것은 아래 두 가지다.

1. `SetupStep`을 문항 수집 중심의 `COLLECT` 화면으로 교체
2. `StrategyStep`을 “문항 리스트 + 진행률 + 시작 버튼” 중심 허브로 재설계

- 해야 할 일이 명확하다
- 내가 눌러서 다음 단계로 간다
- 한 문항씩 끝내는 구조다
- 기존의 강력한 AI 기능은 필요할 때 펼쳐진다
